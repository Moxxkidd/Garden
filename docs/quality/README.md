# Garden 质量基线与发布准备

v1.0 的验收目标是资产发现和可追溯清单质量。`corpus-v1.json` 是版本化检查清单，覆盖原路线图的六个维度。它引用既有行为测试；不是把测试通过率当作资产发现率。

## 运行

在源码仓库使用项目支持的 Python 3.10 或 3.12，安装 `pip install -e '.[dev]'` 及 `python -m playwright install chromium --no-shell`，执行：

```bash
python scripts/quality_baseline.py
python scripts/quality_baseline.py --full --output .verification/quality
```

第一个命令运行固定质量检查，第二个运行一次全部 pytest 并从同一次结果提取质量门禁。不要把两条命令都作为必需的连续发布步骤。浏览器串行运行，站点使用合成数据和本地回环地址；需要允许本地监听与 Chromium 启动。脚本依赖源码中的 tests 和 docs，不是安装后面向目标的扫描命令。

输出包括 `quality.md`、`quality.json`、`junit.xml` 和 `pytest.log`。JSON 记录 schema `quality-v1`、语料版本、Git SHA、工作区是否有改动、Python/平台、真实执行命令与耗时。工作区有改动时 SHA 仅标识基线，不能代表全部被测文件。

状态只有 `passed` 和 `blocked`。pytest 非零退出、必需用例未找到、失败、错误、跳过、指标缺失或分母为零均阻塞。参数化用例的所有实际执行分支必须通过；完整模式中非门禁测试失败或跳过也会阻塞。用例节点改名时必须同步检查清单，不能静默丢弃。

## 指标定义与限制

| 指标 | 分子 / 分母 | 门槛 |
| --- | --- | --- |
| 发现召回 | 浏览器实际观察到的预期路径 / 明确列出的 3 个预期路径 | 3/3 |
| 候选确认 | 已观察到的同源可自动访问 GET 候选路径 / 此类候选路径 | 全部；分母非零 |
| 误合并率 | 被合并的不同路由族样本对 / 固定语料全部不同族样本对 | 0 |

浏览器语料复用 `tests/test_discovery_browser.py` 的回环站点，包含延迟 fetch、两个 hash 路由、POST 与跨域请求；指标按 URL path 去重。两个 hash 的具体请求与 POST 禁止发送另外由必过行为检查验证，不由路径指标代替。归并语料覆盖不同 origin、方法、编码路径和重复参数名；同参数名的不同值在公共路由族层允许归并，精确请求变体不是这个指标的判定对象。

Sitemap、认证后采集、登录失效、软 404、导出完整性/脱敏、来源删除后的快照、覆盖下降与续跑身份校验通过独立行为检查验收。它们没有伪造数值召回率。真实站点没有已知全集，只报告已观察、候选、未知和覆盖限制。

## 发布门禁

- Linux 的 Python 3.10 和 3.12 完整检查、CLI smoke、Docker build 全部通过；CI 附件分别保存 `quality-python-3.10` 和 `quality-python-3.12`。
- 跨站误合并、身份串用、导出泄密、越界和非幂等自动请求相关行为检查必须通过，不允许通过改成 skip 绕开。
- wheel/sdist 包资源及安装后的 CLI/Web 冒烟有独立证据；pytest 通过不替代打包验证。
- 无新增数据库迁移，保持迁移 `0011`。发布前核对项目版本、真实 tag 与安装升级说明；当前实现不创建 tag、release 或上传包。

此处的门禁是软件发布准备证据，不是针对真实目标的完整性保证，也不是独立安全审计。
