# v0.8 持久采集与补采

本记录使用独立临时数据库和合成目标，不包含真实登录信息。本地验收版本 0.8.0；Linux 未验证，尚未发布。

## 从任务查看队列

新建扫描时显式启用持久采集并设置请求预算。任务页进入持久采集队列，分别查看执行状态、已知工作覆盖、发送尝试和响应。队列 ID 用于查询工作和补采，任务 ID 用于查本轮结果，两者不能互换。

暂停只阻止新增发送，不撤回已发出的请求。已经开始的请求可以收尾；未确认响应的发送窗口保留“可能已发送”，不伪装成未发送，也不退款绕过预算。服务重启不会自动访问目标。

## 预览再恢复

在队列页展开「预览新一轮补采」，选择模式和预算。预览不访问目标，显示原轮已用预算、新预算、可恢复项、不可恢复材料及未完成原因。全部材料不可恢复时没有确认按钮；材料或配置变化后必须重新预览。

- 仅已知工作：补采选定的已知缺口，不继续扩展新链接。
- 继续同源发现：允许从选定工作继续发现，仍保留目标、身份、范围和预算限制。

确认后建立新任务。原轮未完成事实和原报告不改写；新轮观察独立保存。身份恢复需要有效登录态并重新验证，不会偷偷改成匿名扫描。

## 指标怎么读

发送尝试包含验证和重试；确认观察不能拿未确认身份的响应补数。观察比例在零分母或旧记录缺指标时为未知。候选重复与工作重复入队是不同指标，不能相加当作资产数。

活动、等待和冷却记录采集器的墙钟时间，不是 CPU 用时。证据字节是预算计费材料，不是数据库磁盘大小。项目新增主体与新增观察在本轮收尾时冻结；之后独立重试入库不改写历史指标。未关联项目为不适用，入库失败或旧记录未测量为未知。

## 边界与恢复材料

原始请求材料保存在受保护目录中，不能只备份数据库而丢弃这些文件。路径损坏或材料丢失会显示不可恢复，不会凭脱敏 URL 猜测原请求。文件与 SQLite 不承诺跨系统原子提交；运行中不要按目录差集自动删除所谓孤儿文件。停止写入、核对全部已提交引用后，才能进行离线维护。

单机 SQLite 调度采用有界工作线程和执行器锁；不支持分布式 worker。实际万级实验、进程中断与环境限制见[实验记录](benchmarks/v08-collection.md)。
