# Garden v0.6.0：身份辅助资产采集

状态：用户于 2026-10-03 批准技术设计；实施计划已编写，尚未实现。
基线：main 5cbbe38，v0.5 PR #35 已合并。

## 目标与验收场景

让用户只提供一个普通账号也能采集资产；遇到验证码、短信或扫码时由用户人工完成，保存的会话必须在独立浏览器上下文中恢复并验证成功。匿名与多个登录身份进入同一任务、同一资产清单，主体归并与身份观察分开计数。身份中途失效时保留此前结果，指出待补采范围，并允许重新认证后创建关联的补采任务。

保留 quick 和匿名/user/admin 三上下文 authenticated_coverage 专门模式。v0.7 跨任务项目资产库、任意历史任务合并、分布式采集不纳入本版。

本版交付包含 Web、CLI、API、JSON/CSV、Markdown 报告、README、展示页、数据库迁移及完整测试。

## 当前代码限制

- AssessmentStartRequest 要求认证覆盖同时提供 user/admin；ScanContext 按 run/kind 唯一，不能容纳两个普通用户身份。
- ContextEstablishmentService 和 ScanPipeline 的建立、采集、汇总逻辑以固定三身份为前提。
- AuthSessionService 已支持登录、验证、刷新和独立存储；Playwright 适配器能恢复 storage_state，但只支持自动填写登录。
- SessionStorageService.write_payload 尚未采用请求材料的 0600 原子创建方式，人工导入前需要统一权限与写入约束。
- v0.5 统一清单已经能按路由聚合不同观察，应扩展身份元数据与矩阵，而不是重新造一套资产清单。

## 方案选择

采用“新增通用身份采集模式 + 共用有界浏览器采集器 + 现有统一资产投影”。新增独立身份任务编排服务，复用生命周期、网络范围、发现解析和报告基础设施，避免继续向固定三上下文分支追加特例。

不选择把单账号伪装成 user/admin 两个角色：这会伪造覆盖和身份数量。也不选择独立身份资产数据库：这会破坏统一清单与导出目标。

## 1. 单个或多个身份采集

新增 identity_collection 模式。请求提供目标、1—10 个去重后的凭证档案 ID、是否包含匿名，以及现有 ScanOptions；匿名单独采集允许空档案列表且 include_anonymous=true，两者都空则拒绝。档案必须属于同一 target，入口必须同源。新增模式只做被动采集，拒绝主动重放开关。

Web 提交入口选择身份，显示显示名、档案 ID、最近验证状态和时间；角色标签是用户提供的说明，不宣称已验证实际权限。CLI 提供重复的 --profile-id 参数及 --include-anonymous。API 使用同一请求校验及预览服务，重复提交仍依现有任务去重机制处理。

每个上下文由稳定 context_key 标识：anonymous 或 profile:<id>，不以可重名的显示名或 user/admin 角色作唯一键。旧 kind 和三上下文输出保持兼容；新增身份观察增加 context_id、profile_id、显示名快照。新增模式拥有独立身份计数，不能塞进旧 context_counts 冒充 user/admin。

数据库迁移 0008 扩展上下文标识、身份快照、会话健康检查点及补采引用；将唯一约束调整为 run/context_key。旧任务回填已有 kind 作为 context_key；保持旧 ID、外键和证据引用。无法无损恢复旧唯一约束时降级必须拒绝，不丢记录。

## 2. 人工登录与导入

身份页提供“开始人工登录、验证并保存、取消、重新验证、撤销”动作。登录本身不启动扫描。验证码、短信、扫码均由用户在专用浏览器窗口完成，Garden 不识别、代填或绕过挑战。

人工登录首版面向 Garden 运行机器的可见 Chromium 窗口，页面明确说明窗口打开位置。无显示环境不能显示假成功，应提示使用本地 Garden 完成人工登录后导入受支持的状态；本版不建设远程桌面或把服务端窗口冒充用户电脑上的窗口。

新增有期限的登录尝试记录，由单独的浏览器工作线程拥有 Playwright 对象；HTTP 请求只通过有界命令队列与其交互。流程：created → waiting_for_user → validating_restore → ready；另有 failed、cancelled、expired。默认 15 分钟，最多允许本进程同时 3 个登录窗口；重启后未完成尝试标记 interrupted，不把残留状态标记 ready。

点击“验证并保存”后，采集允许范围内 Cookie、localStorage 和需要时的 sessionStorage；在新建隔离上下文恢复，再访问用户配置的同源验证页。必须满足正向登录标志（明确 selector/text 或已配置的验证响应条件），不以 HTTP 200、Cookie 非空或离开登录 URL 单独判断成功。保存快照失败、恢复失败或验证失败均不产生可用身份。

导入接受有界 UTF-8 JSON 的 Playwright storage_state 与 Garden 版本化 sessionStorage 扩展，最大 1 MiB。允许的 Cookie 域、origin 和键类型逐项校验；拒绝或明确报告范围外状态，不能悄悄跨站加载。缺少必要状态时验证失败并说明尚不支持，不臆测可以恢复。首版不承诺设备绑定、内存 token 或任意 IndexedDB 登录可迁移。

默认登录导航限定 target origin。需要第三方 SSO 的用户必须显式配置精确认证 origin 白名单，仍受现有网络地址策略约束；该名单仅用于人工认证，不扩大扫描 origin。登录过程允许用户所需的提交请求；扫描过程仍仅允许 GET/HEAD。验证后持久化仅保留采集目标所需状态。

## 3. 登录态保护与生命周期

统一受保护状态目录权限 0700、状态文件权限 0600，使用不可预测文件名、原子替换和受控目录校验；不接收客户端任意服务器路径。公开模型不包含 Cookie、token、原始状态、验证码或本地完整路径。仅向客户端返回会话 ID、状态、时间、脱敏诊断和存储能力说明。

一次成功重新认证创建新的会话版本；运行中的上下文固定到启动时选定会话，不能中途悄悄换身份。撤销阻止新的采集及后续发送，释放浏览器资源；保留审计和历史响应。过期时间未知时显示未知，不能伪造长效。

人工登录失败或用户取消时关闭窗口及上下文，清理临时状态；确认成功后的会话才可复用。服务端崩溃和过期尝试由启动清理及惰性清理处理。

## 4. 开始前与扫描中健康检查

每个身份启动前必须执行恢复验证。采集使用独立上下文、Cookie jar 与状态文件，禁止身份间复用可变浏览器状态。其他身份失败不能回滚已成功身份的响应。

复用 v0.5 有界 GET/HEAD 浏览器发现能力，支持同一套 HTML、Sitemap、JS、URL/OpenAPI 来源及 Hash 路由规则；认证状态作为受控采集上下文注入，不加入公开 ScanOptions。浏览器每次发送前执行范围、取消与预算检查。

默认每 20 次允许请求或 30 秒（先到者）执行已配置的会话验证；批次结束前再验证一次。验证请求计入请求预算，单独标为健康检查用途，不增加业务资产主体数。没有预算完成验证时终止该身份并记为无法确认，不宣称会话仍有效。

401、403、登录页跳转和登录 DOM 特征只触发复查，不单独等价于退出登录（有效身份也可能无权访问某个资源）。若明确验证失败，停止该身份后续发送。自上次成功检查后尚未确认的一批响应标为 identity_uncertain，保留证据但不作为已验证身份业务观察；已确认登录回退作为认证诊断，不把同一登录页铺成业务资产列表。其他身份可继续执行。

用户可看到 ready、checking、expired、validation_failed、unknown，及检查时间和失败原因。执行完成、身份有效性和覆盖完整性分别展示。

## 5. 统一主体、身份观察和可见性矩阵

继续使用 route-v1/hash-v1 聚合主体：同站点、方法、类型、路径及参数形状相同的资产显示一个组，但保留每个身份的全部响应、状态码、有效性线索、请求与证据关联。原始记录计数不改成主体数；页面并列显示主体数、身份观察数和候选数。

矩阵行是主体，列是本任务选择的上下文（以 context_key 定位，显示名可重名）。单元格显示“已观察响应（含具体状态码）”“身份未确认”“本次未观察到”“未完成/未知”。未采集、失败或过期身份不得显示成无访问权限；401/403 保留真实状态，但不自动推导漏洞或授权结论。

URL 相同但身份响应不同不能被统一响应、软 404 等规则跨身份误判。现有有效性规则继续按 context_id 隔离。API/JSON/CSV 保留 profile/context 标识和健康状态，Web/CLI/Markdown 使用同一投影；旧结果缺少元数据保持 unknown。

## 6. 重新认证后的补采

失效上下文保存已发现但未完成的工作项，以及 identity_uncertain 的重验工作项。精确 URL/路由只在受保护检查点中保存；公开页面显示脱敏样例、已知数量和未知边界。采用有界持久队列，不能只在进程内保留。

用户重新认证后点击“补采此身份”，创建独立任务并关联 parent_run_id、source_context_id 和 checkpoint 版本，保持原任务及其报告不变。新会话必须属于原 target/profile；补采前再次验证身份。只恢复已知待补范围，不重复全部成功身份，也不宣称补齐尚未发现的页面。

检查点缺失、版本不支持或目标配置变化时明确拒绝恢复，提供创建新扫描入口；不悄悄当作完整恢复。补采返回独立清单和原任务链接，本版不实现 v0.7 项目级跨任务合并。

## 7. 实施顺序与测试门槛

先编写失败测试再实现对应最小闭环；每阶段保持旧三身份模式可用。

1. 模式与上下文契约、迁移：单档案、多个同角色档案、匿名单独、空选择、跨 target、重复档案；升级旧库保留 ID，无法无损降级时拒绝。
2. 状态导入与健康验证：无凭据的正向验证拒绝、脱敏、权限、文件替换失败、非法域、过大输入、失效状态、撤销；任何公开响应不包含秘密。
3. 人工浏览器登录：真实本地验证码夹具，测试人工动作完成后保存、关闭、新上下文恢复验证；取消、期限、无显示环境、重启与线程清理。
4. 单/多身份采集：一个普通账号独立生成清单，两个同角色账号隔离，匿名可选；v0.5 六种来源进入同一投影，所有自动采集禁止写请求。
5. 失效识别：有效会话的正常 403 不冒充失效；中途退出、登录页回退、检查请求失败、预算耗尽时停止并保留已确认观察，其他身份继续。
6. 矩阵与补采：主体不按身份膨胀、响应差异不丢失、unknown 不变成缺席；同身份新会话恢复待补队列，原报告不被覆盖，错误身份/目标拒绝恢复。
7. 真实 Web/CLI/API/导出/报告闭环：桌面/窄屏、无 JS 表单基本操作、凭据内容不回显、当前筛选导出一致。
8. 全量 pytest、Ruff、格式、迁移与打包、独立审查；实际运行固定认证夹具，再据输出更新 README 与展示页。

## 不可混淆的边界

- 用户完成人工挑战不等于恢复登录成功；必须独立验证。
- 单次 HTTP 200 不等于身份有效，403 不等于身份已过期。
- 扫描任务结束不等于所有身份完整，补采完成不等于发现了全站。
- v0.6 的矩阵与补采仍以任务为边界，不提前承诺 v0.7 项目资产库。
- 首版人工登录窗口在运行 Garden 的机器上；远程部署需受支持的状态导入，不能宣称浏览器窗口自动出现在远程用户电脑。
