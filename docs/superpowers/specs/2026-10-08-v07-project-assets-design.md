# Garden v0.7.0：跨任务项目资产库

状态：用户已批准实施；项目核心、API、CLI 与原生 Web 已实现，2026-10-10 正在完成回归和发布准备。独立审查尚未通过，不宣告 v0.7 完成。
基线：origin/main `1529fe67993c58cd7fed4bf8f2cd4cc4ea2274e1`（v0.6 PR #36）。
来源：桌面《Garden资产扫描与聚合能力版本迭代评估-2026-09-25.md》第 7 节；用户已授权推进 v0.7 六项路线能力。

## 1. 目标和成功场景

用户在一个项目里查看多个入口、多个任务积累的已知资产，保留每条观察的来源、身份和时间。资产主体是版本化路由族，不宣称业务实体等价、资产仍然在线或站点发现完整。

闭环：创建项目 → 绑定已有 Target 与入口 → 关联扫描／inventory 任务 → 预览并入库 → 搜索项目清单 → 查看历史、变更和关系 → 标签／备注／纠正 → 导出当前筛选结果。

必验例：同站点同路由在两个任务分别匿名返回 401、普通身份返回 200，项目中是一个主体、两条观察；另一个 origin 的同名路径是另一个主体。第三次登录失败不能删除前两次观察或标记资产消失。

保留现有单任务清单、匿名 quick、固定三身份覆盖、v0.6 身份采集及补采入口。v0.7 不改变采集网络授权，不把项目成员资格当作扫描许可。

## 2. 代码核对和方案取舍

- `AssetCatalogService` 只投影单个 scan/inventory；复用其脱敏记录、候选及范围元数据，不读取受保护请求／会话文件。
- `asset_grouping.route_key()` 包含站点、方法、原始类型、路径、参数名重复次数及 Hash 路由；现有 group ID 带来源任务编号，不能作为跨任务主键。
- `ScanComparisonService` 的可比判断针对旧匿名扫描；不能直接将其限制去掉用于多身份项目比较。
- Target、CredentialProfile 与 ScanContext 已有独立身份绑定；项目层不合并凭证档案，不按显示名识别账号。
- 当前迁移 head 为 0008；v0.7 使用增量迁移 0009。

比较过三条路径：临时拼接全部任务无需新增库，但稳定 ID、人工整理与查询成本难控制；替换现有采集存储会扩大迁移风险；推荐新增持久化项目索引和不可变观察快照，复用原任务作为证据来源。代价是新增入库状态、索引和同步恢复逻辑。

## 3. 项目、多入口与任务入库

Project：名称、说明、active/archived、创建时间。归档禁止新增入口／入库，已有记录可读；首版不提供硬删除项目或级联删除源任务。

ProjectEntry：project、target、同源入口 URL、名称、启用状态、创建时 origin。多个 Target／origin 可属于一个项目，同一个 Target 可用于多个项目；数据与人工整理在项目间隔离。精确 origin 包含 scheme/host/有效端口，不把子域或 HTTP/HTTPS 自动归并。入口路径是任务启动入口，不暗示额外路径级授权。

新增入口校验 Target 当前有效、入口同源，保存动作不访问目标；修改 Target origin 后旧入口标记需要重新绑定，禁止静默扩大范围。项目内执行扫描仍经过原提交预览、范围检查和身份选择。首版保留逐入口启动，不添加跨站点批量调度。

ProjectRun：project、entry、source(scan/inventory)、run ID、来源目标与入口快照、入库版本、状态、错误码、记录数。状态 pending/importing/complete/failed；唯一约束避免同一项目同一来源任务重复关联。一个任务允许加入多个项目。

历史任务必须显式选择来源、预览、确认。预览只读，显示主体／观察／候选预估量、缺失信息和不匹配理由；确认重新校验任务及入口快照，拒绝过期预览。running 任务不提供历史入库，终态不完整／失败任务允许保存已有观察与覆盖限制；零观察仍保存任务覆盖快照，不伪造零覆盖结论。

新任务可在已有提交流程显式选择项目入口，成功创建任务后建立 pending 关联。任务到达终态后触发入库；项目索引失败不得改写扫描状态或历史报告。提供显式同步／重试入口处理进程中断后的 pending/failed 记录；浏览页面不会隐式写入或访问目标。

入库在一个事务中写入快照、更新计数和标记完成；并发／重复确认／重试由唯一键及事务保证幂等。来源任务终态数据若与已入库摘要不一致，返回 source_changed，不覆盖快照；修复或迁移须另外设计。源任务缺失时保留项目快照、标注证据源不可用。

## 4. 稳定主体、观察和候选

ProjectAsset 使用持久化独立 ID，唯一自然键包含 project ID、project-route-v1 规则版本和规范化路由材料。复用 route-v1/hash-v1 的形状语义，去掉任务命名空间；保留路径大小写、尾斜杠、编码斜杠、重复参数名和 Hash 路由差异。类型使用现有原始类型，避免新猜测导致错误合并。

主体键不包括查询值、Cookie、凭据、响应内容或身份；不把密钥哈希作为公开 ID。缺少 origin、方法或无法可靠解析的旧记录使用来源记录隔离键，标注无法归并，不猜测默认值。未来规则变化不得静默改写既有 ID。

ProjectObservation 保存显示安全的不可变 AssetRecord 快照、来源 record ID、source/run/context/profile 标识、采集时间、证据与请求 ID 引用、有效性及身份判断。唯一键包含项目、来源、任务、记录类型和记录 ID。原记录内的多次 identity_observations 保留原关联，不将最新 401 填入历史已确认 200 的证据格。

身份比较使用 target + profile ID；anonymous 使用目标范围内的匿名键；旧记录缺少可证明档案关联时按来源上下文隔离，角色／显示名不能当作同一账号。档案名称和角色保存当时快照，改名不改写历史。

首次／最近观察按源记录采集时间计算，不按入库时间；乱序导入旧任务不能让最近结果回退。缺失时间保持 unknown。显示最新属性必须关联具体观察；同一最近批次有冲突时列出差异，不任意挑选一条。已有响应、身份已确认、业务有效性仍为独立维度。

候选保存在独立 ProjectCandidate，不计入已观察主体；同一候选可链接后来观察到的主体，但保留原声明和来源。查询同时给出主体数、观察记录数、候选数及计数范围。

## 5. 历史与变更

历史清单始终保留已知资产，不用最近一次任务覆盖整个项目。首次发现指当前已导入历史中的最早观察，不宣称全站首次出现。

变更比较首版显式选择两个已入库来源任务，按入口／origin／身份分组；不把无关入口的最近任务拼成一个隐式完整快照。结果包含 newly_observed、attributes_changed、unchanged、not_observed、unknown，并提供原因与双方证据。

可比条件：同一项目、相同绑定目标／origin、相同入口、相同模式和发现选项／预算、相同归并规则、可证明的同一身份上下文、双方采集材料足够。身份失败、预算截断、覆盖不完整、配置变化、缺少元数据或历史时间不明时缺席结果为 unknown；可以展示双方实际属性，但不宣称可比变化。

同身份已观察响应从 200 变为 404，显示“观察响应变化 200→404”；完整可比轮次没有观察则显示“本次未观察到”。没有 deleted/已下线自动状态，不把前两种情况等价为资产消失。补采仅覆盖已知缺口，不能用来推导项目内未出现在补采结果的资产消失。

## 6. 关系与人工整理

ProjectRelation 保存 page_reference、script_hint、redirect 三类有明确来源的关系及来源任务／观察／证据引用。仅从已保存 discovery、来源 URL 和重定向材料提取；找不到端点记录时链接候选或保留无法解析说明。声明关系与实际请求关系分开，不能由同域、同目录猜测调用关系。禁止读取 protected payload 来补关系。

首版 Web 展示可过滤的关系列表和资产详情中的入边／出边，无需新增图可视化依赖。导出保留关系类型、证据、候选标记。

人工整理包含标签、备注、归并纠正及追加式审计记录。标签每项最长 40 字、每资产最多 20 项；备注最长 2000 字；HTML 转义、CSV 公式防护及现有脱敏规则全部适用，提示不要填写凭据。

纠正采用可撤销的展示规则，不删除／改写观察、自然键或主体 ID：
- 合并：仅允许同项目同 origin／方法／类型／规则版本的主体人工合并展示；选定保留主体并保存别名与原因，禁止自合并、环和重复冲突规则。
- 拆分：从一个主体中显式选择现有观察记录，建立稳定人工子主体并记录来源；禁止将同一观察同时分配给两个有效展示主体。
- 撤销：撤销整条纠正规则，恢复原归属；标签／备注仍附着原稳定 ID，不静默迁移或丢弃。若后续有效纠正依赖该规则，拒绝直接撤销并展示依赖。
- 新观察继续按默认自然键入库，拆分不根据脱敏参数猜测未来归属。UI 明示哪些纠正只覆盖已选历史观察。

纠正预览展示前后主体数和观察归属，确认使用版本校验；审计包含动作、原因、时间及现有可信操作者标识，系统没有可信身份时记 local_operator，不伪造实名归属。

## 7. 查询、交付与规模边界

新增项目服务层及独立 schemas，不改变现有 `/assets` 的单任务参数与含义。Web 项目列表／详情／资产历史／变更／关系／整理表单、CLI `garden projects`、API `/api/projects` 共用服务及校验；项目结果页面标明数据截止范围与最近入库状态。

筛选：站点、类型、方法、身份、来源任务、候选／观察、标签、关键词、时间；稳定排序以持久 ID 为末级键。分页默认 50、最大 200。SQL 查询和索引承担跨任务筛选，不在每次请求临时加载全部任务并重新归并。

JSON/CSV 按资产、观察、候选、关系分别导出，带 schema_version、project ID、筛选与 exported_count，独立于页面分页；保持相同筛选口径。Markdown 概览提供计数、已知覆盖限制及证据入口，不替代完整导出。导出期间采用一致读快照，不能因并发入库漏行／重复或静默截断。

数据库迁移 0009 新增项目相关表／索引，不自动把历史任务加入项目，不改旧任务 ID 或数据。没有项目数据时可降级；有新增项目数据时拒绝有损降级。保守复用现有 Python、SQLAlchemy、FastAPI、Typer、模板和 Chromium，不增加服务依赖。

首版以合成 1 万条观察验证入库幂等、分页和导出完整性；记录本地耗时作为基线，不承诺未测的生产吞吐。v0.8 持久化调度／站点并发／限流退避、v0.9 外部系统集成不纳入本版。

## 8. TDD 与验收边界

1. 迁移旧库数据不变；跨 origin、方法、参数名重复次数、Hash 路由不误合并；跨任务 ID 稳定，缺字段单独保留。
2. 多入口与 Target 改动校验；未绑定或范围不匹配任务拒绝；只读预览不访问目标、不写状态；确认过期拒绝。
3. 相同任务重复／并发入库计数不增；事务故障回滚、重启重试；乱序入库不回退最近观察；归档拒绝新入库。
4. 匿名 401／用户 200 同主体两观察；同名不同 profile 不混同；历史身份不确定不覆盖确认材料；候选与观察分开。
5. 完整／不完整、失效身份、缺元数据、变更范围和补采比较矩阵；任何覆盖不足都不产生“消失”结论。
6. 关系只来自保存证据；人工合并／拆分／撤销不丢观察，跨站点合并、环、陈旧确认和并发纠正被拒绝。
7. Web/CLI/API/JSON/CSV/Markdown 计数与筛选一致，分页导出无截断；恶意标签、公式、敏感查询及未知字段不泄漏。
8. 实际本地浏览器：两个入口、多轮单／多身份采集、入库、查看历史与关系、纠正后撤销、导出。窄屏和无 JS 基本操作验收；只按观测结果更新 README 和展示页。
9. 全量 pytest、Ruff、格式、diff、迁移、wheel 资源、独立评审；未执行的平台／性能条件明确标注。默认仅本地交付，推送／PR 需后续明确指令。
