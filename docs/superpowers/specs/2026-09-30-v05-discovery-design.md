# Garden v0.5 发现能力增强设计

状态：用户已批准，按本方案实现并验收。基线：main 97cd701（v0.4.2）。

## 目标与交付范围

按 2026-09-25 原路线图完成六项发现能力：静态页面、站点地图、匿名动态页面、前端路由、JS 线索、用户种子输入。每项结果进入现有统一资产清单，保留来源、采集身份、响应和限制，支持 Web、CLI、API 与 JSON/CSV。只报告实际观察与候选，不声称真实站点发现率或业务有效性。

整个 v0.5 分阶段实现和测试，各阶段不单独冒充整个版本交付。v0.6 人工登录、项目资产库、跨任务增量恢复仍按原路线保留在后续版本。

## 现状依据

- `app/services/scan_network.py` 的 `_HTMLMetadataParser` 已处理 a/link/script/img/iframe，但仅保留 URL 和初始类型，未处理完整发现来源、base、srcset 和表单。
- `app/services/scan_pipeline.py` 的 quick 队列按 URL 去重；v0.4.2 只在正常收尾时保存未请求候选。
- `app/services/context_collection.py` 的匿名采集另有 HTTP 队列，应共用发现解析规则，保留固定匿名/user/admin 模式。
- `app/integrations/inventory/playwright_gateway.py` 已实现页面浏览和 XHR/fetch 观察，但依赖 session 入参、去除 fragment；max_requests 当前主要限制响应记录，不能直接宣称限制所有浏览器网络请求。
- `app/services/asset_catalog.py` 提供统一投影与有效性线索。新增发现来源应扩展此投影，不另外建立一张互不相通的资产清单。

## 方案选择

推荐复用现有采集器，新增共用发现解析与预算模块。HTTP 和浏览器仍负责各自的传输与响应捕获，共用来源模型、范围检查接口和输出投影。

替代方案一是另建完整爬虫服务，隔离较强但会重复会话、范围、任务生命周期和导出实现。替代方案二是在两个现有大文件中分别追加功能，短期改动少但解析、预算和来源语义容易分叉。两者均不采用。

## 共用数据语义

新增结构化发现项：目标 URL、预期资源类型、方法（可未知）、source_kind、source_url、源任务/身份、可选父观察 ID、可选路由视图、是否允许自动访问、未请求原因。

source_kind 包括 entry、html_link、iframe、resource、form_action、sitemap、browser_navigation、browser_request、hash_route、js_literal、url_import、openapi_import。未知旧记录使用 unknown，不能回填猜测来源。

同一地址可有多个来源。请求去重和来源去重分开：不重复请求不意味着覆盖掉其他来源。来源按规范化地址、方法、身份与来源类型去重，并设每项最多 20 个展示来源；超出时提供截断标志；精确来源总量保持未知，展示列表数量仍可见。精确请求材料继续走受保护存储，常规来源 URL、导入内容与路由查询值均脱敏。

所有源先产生候选。只有收到实际响应才增加已有响应观察；失败、超预算、超深度、越界和仅声明候选分别记录原因。仅存在 OpenAPI 描述、JS 字符串或表单 action 不证明接口存在。

将现有候选元数据演进为版本化持久结构，保留 v1 读取兼容。扫描中按采集批次保存发现项，异常收尾保留已保存部分并标注来源记录不完整。inventory 增加可空发现元数据，旧记录保留未知。数据库使用新增迁移，不重写历史记录或破坏旧 ID。

## 控制项与范围

已有 quick / authenticated_coverage 任务模式保留。新增 quick 采集方式 http（默认）或 browser；浏览器模式不需要凭据、账号或虚假的认证会话。

增强静态解析默认启用。sitemap、JS 线索和匿名浏览器作为显式可选项；旧任务缺少字段时使用兼容默认值。提交预览、配置复用、CLI 与 Web 同步呈现已选来源及预算。

建议新增预算默认值：max_candidates=2000（上限 10000）；max_sitemap_documents=10（上限 50）；max_sitemap_depth=2（上限 5）；max_browser_requests=300（上限 2000）；render_wait_ms=1000（上限 5000）。仍共用整体期限、页面数、资源数和重定向上限。sitemap 响应沿用 HTTP 256 KiB 正文上限；导入文本上限 1 MiB、最多 1000 项。上限前停止继续入队，并返回结构化覆盖缺口。

所有主动访问限定起始站点的规范化 origin。相对 URL 以实际最终响应地址为基准；base 标签可以影响解析，但不能扩大允许范围。重定向、浏览器子资源和地图子索引都必须经过请求前范围及网络策略检查。外域来源保留为未访问依赖，不自动追踪。

浏览器请求预算应在发送前计数；每次重试与重定向跳数计入请求尝试统计。达到预算或任务取消时停止发出后续请求，保留已观察记录并显示不完整。不得把“停止记录响应”当成“停止发请求”。

## 六项功能

### 1. 静态页面与资源

提取 a/area href、iframe src、script src、stylesheet/preload/icon、img/source src/srcset、audio/video src 与 video poster。正确处理相对路径、有效 base、HTML 实体及重定向后的基址。纯锚点、非 HTTP(S) 地址和空值不入访问队列。

表单记录 action 和 method；不构造参数、不提交表单，即使 GET 表单也只记录候选。表单提交按钮的 formaction/formmethod 作为独立候选来源保留。

### 2. sitemap

支持 URL set 和 sitemap index；默认入口为用户指定 sitemap，未指定时使用同站点 /sitemap.xml。仅在启用 sitemap 时访问。索引递归共享文件数、深度、候选数与整体时间预算，循环引用去重。

初版只支持受大小约束的 XML，不解包 .gz，不解析 DTD/外部实体。格式错误、超长、截断、非 XML、循环和越界索引分别记录诊断。地图 URL 是候选，按普通队列策略取得响应后才算观察。首版不额外抓取 robots.txt。

### 3. 匿名动态页面

复用 Playwright 网关，创建空 browser context，不读取认证存储。导航后等待 DOMContentLoaded 加有限渲染窗口，不以无限 networkidle 作为完成条件。记录动态 DOM 链接及 XHR/fetch；所有页面与接口进入同一 scan 资产清单。

初版仅允许自动 GET/HEAD 请求；不自动点击按钮、提交表单、登录或执行导入接口。浏览器产生的非只读请求阻止发送，作为带方法的未请求候选记录；该限制在预览、缺口与文档中说明。此约束仅用于新增匿名模式，不静默改变已有认证流程。

缺失 Chromium 时给出可操作诊断，不静默降级并声称完成动态扫描。取消、超时和限额必须关闭本任务的浏览器上下文。

### 4. 前端路由

普通 #section 仍视为文档锚点；#/path 与 #!/path 作为 hash 路由视图保存，不能被 URL 规范化折叠。首版只导航已发现的同站点 hash 路由，不猜测路由，不自动交互。

路由视图以站点、文档路径及 hash 路径/参数名形成独立的版本化标识，参数值作为变体保留于受保护材料。既有 route-v1 不原地改变；新增规则版本并保留旧 ID 解释。不同路由关联各自导航期间的请求；异步归属无法确认时显示来源未知，不伪造精确 initiator。

### 5. JS 线索

只分析已采集且未截断的脚本，不为提取线索额外下载 source map 或执行任意脚本。只识别 fetch、XHR.open、axios 常见调用及明确路由声明中的静态字符串；动态拼接、模板插值和无法解析的表达式标为不支持，不猜测路径。

JS 线索初版作为候选展示，不自动请求。记录脚本来源、调用类型和方法线索，不保存含敏感信息的源码片段。正则/扫描器必须对输入长度及匹配次数有界，不能使用可能导致严重回溯的表达式。

### 6. 输入补充

支持 UTF-8 URL 逐行列表，以及 OpenAPI 3.x JSON 的 servers/paths/operation 方法描述。首版不支持 YAML、Swagger 2、远程 $ref 获取或参数实例自动生成；明确返回不支持说明。

URL 列表中的同站点 GET 种子可进入普通访问队列；OpenAPI 路径声明、含模板参数的路径和非 GET/HEAD 方法只作为候选。每项保留导入来源类型与条目序号；不暴露用户本地完整文件路径。只读取显式提供的本地文件或 Web 上传文本，不自动下载用户给出的远程规范地址。

## 来源收益与用户输出

资产表新增来源类型筛选和来源详情；归并展开后保留各原始观察来源。候选展示未请求原因。CLI 的 JSON 与普通列表、API、JSON/CSV 使用相同投影；导出包含全部匹配结果并说明分页不影响导出。

任务详情、CLI 摘要和 Markdown 报告提供按来源的 discovered、new_candidates、duplicate_candidates、request_attempts、response_observed、skipped 计数。新候选与请求归因给首次成功入队的来源，多来源证据另保留，避免把同一响应重复相加。计数语义明确为该次采集结果，不是站点资产总量；未采集的旧数据保持未知。

README 与展示页使用实际固定测试站点的输出说明各开关、候选语义、收益和限制，不凭设计稿写成已完成。

## 实现顺序与 TDD 验收

1. 共用来源/候选/预算契约与兼容迁移：先测试旧任务读取未知、多来源保留、脱敏、截断、持久化失败/取消和跨身份隔离。
2. 静态解析：先测试相对路径、重定向基址、base、srcset、iframe、表单候选、非 HTTP、超长与重复输入；验证新功能未引入表单请求。
3. sitemap：本地 HTTP 夹具覆盖 URL set、索引、循环、越界重定向、外部实体、大小/数量/深度上限；核对真实发送请求数。
4. 输入与 JS：用本地文件和已采集脚本验证解析边界、导入错误、模板路径、非只读方法及敏感内容；断言不产生隐式网络访问。
5. 匿名浏览器与 hash 路由：本地 SPA 夹具覆盖延迟 fetch、两个 hash 视图、普通锚点、非只读阻断、跨域子资源、预算前置拦截和取消清理。
6. 全表面闭环：真实 CLI、API、Web 有/无 JavaScript、当前筛选导出、预览与配置复用；验证各层计数、身份、来源、缺口保持一致。
7. 全量 pytest、Ruff、格式、迁移/打包、桌面/窄屏实看及独立代码复审。未经用户另行授权不推送、不创建 PR、不合并。

每项功能先运行失败测试再实现，通过后纳入完整回归。测试站点需明确已知资产集合，可计算固定样本召回；真实目标只报告观察与缺口。

## 发布门槛

- 不越界访问、不提交表单、不混用身份、不泄漏参数或 Cookie。
- 候选不计入已有响应，重复来源不虚增响应数，有限预算不报告覆盖完整。
- hash 路由不被静默合并；不同站点/方法仍隔离。
- 旧库升级保留记录与引用，旧任务未提供来源时仍可查询和导出。
- 六项模块及 Web/CLI/API/导出均通过验证后才标记 v0.5 完成。
