# v0.4.1 可信归并实现边界

依据桌面评估报告的 v0.4.1：区分资产、请求变体、观察记录；归并规则版本化；保留来源及原始证据关联。

## 合同

- 新增 records / grouped 视图，默认 records 保持旧计数。Web、CLI、API、JSON/CSV 共用同一结果服务。
- route-v1 使用规范化 origin、方法、原始类型、精确路径、查询参数名及重复次数。仅在单一来源任务内归并；保留每条原资产记录。不推断业务等价。
- 无效 URL 或未知方法独立保留。路径大小写、末尾斜杠、百分号编码保持保守区分。不尝试从已移除的 hash 路由还原页面视图。
- 过滤先作用于原始记录，再分组；组内只包含匹配记录。total 和类型分布为全任务组数，matched 为过滤后组数，matched_observation_count 为过滤后原资产记录数。
- grouped schema 1.1；每组含 rule_version、observations、variants、变体数（可空）、原始请求/证据 ID。组 ID 为公开路由身份的摘要加来源任务前缀，不输出私有请求指纹。
- 新请求指纹 v2 区分方法、完整 URL、请求体与请求头。身份上下文之间不合并变体；响应状态/稳定内容差异保留独立捕获记录。完全相同捕获去重，不宣称保留每次重复网络事件。
- 新响应快照只保存 request_id 对应状态码和脱敏内容类型，普通读取不访问受保护请求材料。旧指纹、资源观察、quick scan 和 inventory 缺少精确变体信息时为 unknown，不依据脱敏 URL 推断相同。

## 采集层与迁移

回归测试发现，单改展示层不足以防止错误聚合：

- context collection 入库查找需包含完整脱敏 URL（含 origin、精确路径、参数名）及资源类型；覆盖比较沿用其旧 identity_key，不改变三身份覆盖分类规则。
- quick scan 资产查找增加完整脱敏 URL 约束；inventory endpoint 查找使用请求 URL 的脱敏形态，保留 origin、参数名及重复次数，避免同名 path 跨站点或参数形态误合并。精确参数值仍不输出。
- 迁移 0005 在扫描唯一约束加入 method，将 inventory 接口唯一约束从 method/path 改为 method/url；旧 ID 和关系保留。已有数据不能满足旧唯一约束时拒绝降级，禁止删记录降级。

## 验收与不包含内容

测试不同 origin/端口/方法/路径/重复参数名隔离、参数值相同响应仍保留、响应差异快照、身份/类型保留、私密材料不出现在三端和导出、分页不影响导出、迁移前后关联不变及降级保护。

不包含软 404/登录页回退/业务有效性判定（v0.4.2）、跨任务资产库、额外目标访问、登录流程变更。不能恢复历史采集已经丢失的数据。
