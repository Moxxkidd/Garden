# v0.5 discovery implementation plan

**Goal:** Deliver all six approved discovery modules through the unified catalog.
**Architecture:** Existing HTTP and authenticated collectors remain. Pure source parsers feed a bounded ledger; a separate anonymous browser adapter shares the ledger and persistence. No new implicit authentication or cross-origin access.
**Spec:** ../specs/2026-09-30-v05-discovery-design.md
**Execution:** User approved requirements and directed implementation. Parent integrates sequentially; independent pure parsers and anonymous browser are delegated under dispatching-parallel-agents. No push/PR in this task.

## Global constraints

Python >=3.10; keep old results readable and missing metadata unknown. Browser GET/HEAD only, form and JS/OpenAPI declarations candidate-only. Candidate cap 2000/10000, sitemap docs 10/50 depth2/5, browser requests300/2000, wait1000/5000 ms. Existing 256KiB response cap. Imports1MiB/1000 items. Secret URL values only in protected storage; no out-of-scope requests.

## Tasks and RED/GREEN gates

- [x] 1. Contracts and discovery ledger (`schemas/scan.py`, `services/discovery.py`, migration0007): test bounded options, distinct methods/routes, multiple sources, truncated provenance, sanitized persistence, legacy unknown. Add scan input protected reference and inventory provenance JSON.
- [x] 2. Static HTML/JS pure parsers (`discovery_html.py`, `discovery_js.py`): RED/GREEN on base/relative/srcset/forms/fragments, static JS calls, invalid/complex inputs. Integrate in `scan_network.py` preserving legacy discovered_urls behavior except nonvisitable declarations.
- [x] 3. Sitemap/import pure parsers (`discovery_sources.py`): RED/GREEN valid set/index, namespaces, malformed/DTD, limits, URL/OpenAPI input. Pipeline performs recursion and network admission; unit parsers never perform I/O.
- [x] 4. Pipeline integration (`discovery_scan.py`, `scan_pipeline.py`, application input storage): integration test actual requested paths, source stats, candidates, persistence after partial failure, no submitted forms/JS calls/import operations.
- [x] 5. Anonymous browser (`discovery_browser.py`): real local Chromium RED/GREEN dynamic links/XHR/hash, request limits before send, blocked methods/origins, cleanup. Versioned route grouping handles hash views without changing historical route-v1 records.
- [x] 6. Projections, CLI/Web/API, previews/reuse, reports: source filtering/details, safe seed inputs, budget controls, consistent summary/export. Test actual adapters and browser interactions with/without JS.
- [x] 7. Migration/release/docs and full verification: independent review, all pytest, Ruff and format, packaging/old DB, demo desktop/mobile. Document only verified behavior.

## Review focus

- Raw imported credentials/queries must never appear in preview, reuse payload or public catalog.
- Redirect aliases and repeated response observations must not lose multiple discovery sources.
- Delayed browser callbacks must not fabricate route initiator attribution.
- Aborts and exhausted budgets must save known candidates and incomplete discovery status.
- Defaults on old tasks must not enable browser, sitemap or JS retroactively.
