## 1. 用户结果与版本范围

在现有匿名 HTTP/浏览器扫描与独立单/多身份采集上，提供可恢复的已知工作队列、按站点/身份受控执行、增量候选与定向补采。每项已完成观察沿用当前扫描证据及项目入库路径。Web、CLI、API、JSON/CSV/Markdown 的状态和统计来自同一服务。

本版一次性交付原路线八项能力，不把队列内核完成称作 v0.8 完成。按分片实施，不扩展至 v0.9 外部集成。

- 持久化候选与工作状态，进程退出后仍能解释未完成内容。
- 按站点和身份共享并发、发送间隔与请求预算；HTTP 和浏览器单独计量。
- 有界分页/日历/参数变体策略；被抑制内容仍作为候选与缺口保留。
- 新线索、重要入口和较旧观察的可解释优先级；不会据“未访问”推导消失。
- 已知失败、身份待重验与未覆盖队列的预览补采。
- 持久限流退避和重复失败冷却，恢复后不立即重试轰炸。
- 请求、单响应、总证据、候选及队列存储上限。
- 新增观察/实际发送、重试/验证成本、排队与退避等分 transport 指标。

兼容边界：现有 quick、固定三身份覆盖、inventory 和历史身份检查点继续可用。新增持久增量执行首先服务 quick 与独立身份采集；固定三身份覆盖/旧 inventory 不伪装为可持久恢复。其入口若收到新增增量选项，须明确拒绝或引导至对应匿名/独立身份流程，不能静默忽略。库存历史仍可导入项目；不重写库存采集器。不能把全库万条观察导出测试冒充万级 URL 实际采集验收。

## 2. 现有实现核实与接口差异

| 当前位置 | 实际行为 | v0.8 必须补足 |
|---|---|---|
| `scan_application.py:ThreadedScanDispatcher` | 线程池派发，待运行回调仅在进程内 | 持久派发记录、单属主租约与恢复确认 |
| `scan_application.py:interrupt_active_scans` / `main.py:lifespan` | 启动时将全部 queued/running 扫描标记中断 | 不误伤另一个仍存活 worker；识别租约与遗留旧任务 |
| `scan_pipeline.py:_collect` | HTTP 页面/资源列表和 seen 集合在内存 | 入队先持久化、完成确认与观察原子提交 |
| `browser_discovery.py:collect` | 浏览器队列为 deque；CDP 拦截逐请求守门 | 页面工作持久化，子请求发送准入与完整计费 |
| `discovery.py:DiscoveryLedger` | 候选/来源收益在内存，随后写快照 | 持久状态是恢复依据；ledger 继续承担展示投影 |
| `identity_recovery.py` | 私有有界检查点、关联新任务，最多 2000 条 | 接入通用补采计划；保留旧检查点接口兼容 |
| `identity_health.py` / `identity_collection.py` | 当前浏览器状态验证、20 请求/30 秒健康批次 | 健康验证也通过统一准入；暂停后重验且不串身份 |
| `scan_network.py:_request_once_with_retry` | 固定短退避，重试在请求函数内部 | 考虑 Retry-After、统一尝试计费和持久冷却；避免双重重试 |
| 项目入库 | 已终态来源快照不可覆盖 | 恢复产生关联新来源，不重开并改写旧报告/快照 |

现有 `ScanJob` 是历史任务记录，并非通用持久队列，不能仅复用其 status 声称解决调度。

## 3. 用户流程

### 3.1 新建采集

现有扫描/身份预览增加“可恢复增量采集”选项和折叠预算设置；默认保持原流程。预览仅读取本地数据，不请求目标、不创建任务或保护文件。确认后先原子保存任务、身份配置快照、初始工作，再派发执行。

项目入口可预览从项目已知观察生成的再观察计划。只有拥有受保护原始请求证明、且仍在原范围内的 GET/HEAD 可执行；公开脱敏 URL 不作为可请求种子。没有原请求材料的历史资产单列不可补采原因，不猜测查询值、不静默遗漏。手动提供新种子仍经现有预览与范围检查。

### 3.2 暂停、中断、恢复

暂停停止新请求准入；已发出的请求在原超时内结束并保存，无法确认是否发出/收到的请求标 `uncertain`。用户取消不自动恢复。

启动服务仅识别失效 worker、整理已知租约和显示待恢复工作，不自动重新访问旧任务目标。恢复先只读预览：原任务/上下文、选中原因、已知条数、不可恢复条数、原预算消耗、新预算及旧未完成原因。

确认恢复生成关联新 ScanRun，原报告、观察和项目快照保持不可变。父工作转交有唯一映射和版本 CAS：并发/重复确认不能创建两个子任务。两类恢复范围：

- `known_only`（默认）：仅选中已知待办；浏览器只允许该已知集合，不自动放开辅助依赖；由此导致渲染受限必须展示，用户可选择重新扫描。
- `continue_discovery`：明确预览将继续从已知入口发现新内容，仍受原 origin/Target 和新预算约束；不可假装为原覆盖范围内的精确补采。

范围/Target/入口/采集配置变更时原恢复预览失效，要求重新建立计划；同一 profile 可在重新认证后补采，但预览必须绑定当时新 AuthSession，实际发送前重新验证。不得由用户账号失败降级匿名并继续标原身份。

## 4. 数据与事务（增量迁移 0010）

新增逻辑实体，具体 ORM 文件按实现计划建立：

- `CollectionQueue`：ScanRun/context、父队列、模式、配置/范围摘要、revision、状态、预算及累计计数；原身份用 target+profile ID，匿名显式标识。公开不返回私有摘要或文件引用。
- `CollectionWork`：队列内唯一请求键、脱敏 URL/route、method、深度、来源、优先级原因、状态、尝试数、not_before、受保护请求引用；重复来源保留有界证据。唯一键使用原始规范 URL+method+hash-route+身份，不能用跨任务路由族键丢参数值。
- `CollectionAttempt`：每次已预留发送的不可变记录、归属租约/预算、请求类别、结果/不确定、状态码、字节计数；关联原证据。无原始 Cookie/令牌/URL 查询值。
- `CollectionLease`：worker/队列、随机 fencing token、到期与心跳；旧 token 不可领取、发新请求或完成当前尝试。
- `CollectionGate`：origin 与 origin+identity 两级的共享占用、next_send_at、cooldown_until；多个项目指向同站点不能绕过限制。
- 恢复关联的唯一键、必要索引、版本化配置；外键删除策略不能级联销毁项目历史。

原始 URL/路由和必要请求材料放受保护目录（0700/0600），随机不可预测引用，不进入常规库字段/日志/导出。沿用存储机制，但新增队列读取必须校验路径范围、符号链接、版本、大小和内容摘要。文件完整写入后才能发布数据库引用；孤儿文件可标记清理，不承诺跨文件系统与 SQLite 原子性。

请求发生在数据库事务外。顺序：短事务 claim + 计费预留 → 读取受保护材料/范围和身份检查 → 最后发送前校验租约并准入 → 网络 → 短事务持久响应/候选/完成状态。发送前检查失败不产生“已发送”，但保留取消的预留记录；崩溃窗口的预留计为 `possibly_sent`，保守消耗预算，不退款后盲目重发。

HTTP 请求不可能与 SQLite 提交原子地 exactly-once。交付保证为：有界至少一次恢复、明确不确定请求、存储按尝试幂等；不承诺网络零重复。已结束来源不回写，新一轮复查形成新观察。

旧库升级不回填伪造的请求状态/效率指标；旧记录显示“未记录”。有队列/尝试/恢复链数据拒绝有损降级。doctor 仍只读，不创建或修复队列。

## 5. 调度、限流与预算

原生 SQLite + 有界线程池，不新增 Redis/Celery 等运行依赖；本版目标为单机，不承诺分布式调度。SQL Session 不跨线程共享；浏览器 context 不跨身份复用。

默认建议（必须同时出现在预览/CLI/Web/API schema）：

| 控制 | 默认与边界 |
|---|---|
| 全局任务 worker | 沿用现有默认 2、上限 8 |
| 同 origin 活动采集 | 默认 1、允许 1–4 |
| 同 origin+identity 活动采集 | 固定 1，避免同账号会话竞争 |
| 最小发送间隔 | 默认 250ms、范围 0–60000ms，所有 transport/重定向/验证共享 origin 门 |
| 总实际发送预算 | 默认 1000、上限 100000；原 max_pages/resources/browser_requests 等继续取更严格限制 |
| 同一工作重试 | 默认 1、上限 2；包含 gateway 原有重试，不叠加两套次数 |
| 候选/队列 | 默认 2000、上限 10000；源输入体积亦有限制 |
| 单响应内容 | 上限沿用 256KiB；默认不因升级放大 |
| 单轮保存证据 | 默认 32MiB、上限 256MiB；计实际序列化内容，不能仅用响应头估算 |
| 路由族参数变体 | 默认 20、上限 200；超过仅暂缓，不删除候选 |
| 连续失败冷却 | 同 origin 连续 3 次 429/503 或传输失败触发 30 秒冷却 |
| 租约 | 初始 120 秒、最多每 10 秒心跳；阻塞调用须有超时，失效 worker 不可继续发送 |

响应内容上限指 HTTP 流式读取/解析及浏览器取回保存的内容；不是 Chromium 全部传输流量或进程内存的硬上限。浏览器未知长度、压缩或分块响应不调用不受限的 body()，保留响应元数据和未完整读取说明；不把完整性缺失伪装成空响应。

每一次重定向、重试、Sitemap、浏览器资源/XHR 和身份验证都计请求预算；不得只计 page.goto。并发上限指活动采集工作/context 数，不虚称限制浏览器所有 TCP 连接数；每个实际请求仍受发送门与请求预算控制。

Retry-After 支持秒数与 HTTP-date。无效值回退到有界指数退避；合法远期值不得截短后提前发送，若超过本轮期限则保留延后工作、结束本轮。冷却持久化，重启和其他身份不能绕过 origin 级退避。等待不占数据库写事务，仍响应取消/截止。

分页、日历、参数组合采用可解释的确定性配额（路由模板/路径段重复/查询名集合），不以正则猜测“业务无效”。参数值仅用于受保护去重，不进入诊断。默认深度和页面上限继续生效。抑制项显示原因，可在新的显式预算预览中重新选择，不能无限自动放宽。

## 6. 增量优先级与可读输出

优先级稳定排序：用户明确选择的重要入口 → 已知失败/待重新认证恢复 → 新线索 → 较旧且可重访的历史观察；同级按入队序号，加入等待老化避免饥饿。重试必须先满足 not_before，优先级不能覆盖范围/身份/退避/预算门。

运行状态、队列状态与覆盖完整性分开。页面示例：

> 本轮执行结束；已保存 120 条观察。还有 8 条待恢复、3 条身份待重验、20 条达到变体上限。已知队列仍未覆盖完整。

统一公开指标：发送尝试、可能已发送、响应数、确认身份观察、身份不确定观察、新增项目主体/观察、重复候选、各类待办/抑制、验证请求、重试、证据字节、活动耗时、等待/冷却耗时。新增项目主体需在入库成功后才计算，未关联项目显示不适用。

“新增有效观察/请求数”以“本轮新增已确认观察 / 实际发送尝试”命名，明确观察不等于业务有效；分母 0/旧记录为 null，不伪造 0% 或 100%。HTTP/浏览器分组展示，不拿单一速度比较。分批浏览器子请求未持久观察前仍可有发送记录，不算已完成资产。

## 7. 拟确认的公开接口与验收边界

1. `CollectionQueueService`：create/get/list_work/enqueue/claim/checkpoint/pause；`CollectionAdmissionService`：reserve/admit/finish；`CollectionResumeService`：preview/confirm。只测试对调用方可观察行为，不断言私有方法调用顺序。
2. 现有 `ScanApplicationService.start_assessment`、`IdentityCollectionService.start` 增加可选执行配置；不删除旧字段。选项冲突在预览时解释，不隐式降级。
3. HTTP `/api/scans/{id}/queue`（按上下文查询）、`/pause`、`/resume-preview`、`/resume`；项目增量计划预览/确认使用项目入口与版本。只读 GET 无网络/无文件写入；POST 使用现有同源保护、体积上限与通用脱敏错误。
4. CLI `garden queue show/work/pause/resume` 和项目增量预览命令；确认默认交互，非交互需要显式确认。Web 在扫描详情、身份上下文和项目入口提供相同入口，手机/无 JS 可用。
5. JSON/CSV/Markdown 使用共享队列与预算投影；零条结果保留元数据，导出不得包含私有请求引用、原始查询、租约 token 或登录状态。
6. Alembic 0009→0010、拒绝有损降级与只读 doctor；真实 subprocess 重启、合成 HTTP/Chromium 站点为独立验收，不用 mock 代替崩溃或浏览器证据。

上述接口是本轮 TDD 确认对象。名称可在不改变语义时按实现简化；若改动范围、身份、恢复确认或预算承诺，先记录并裁定。
