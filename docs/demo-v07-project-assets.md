## 可重复的 Web 流程

从导航进入「项目资产库」，创建项目后绑定已有 Target 和精确入口。入口仅管理结果归属，不扩大授权范围。每个入口分别点击「预览新扫描」，确认后执行原有扫描流程，终态结果自动进入项目；索引失败时原任务和报告保留，可在项目详情重试入库。

本地合成站点分别运行在两个回环 origin，每个站点只有 `/` 与 `/asset` 两个已观察页面。真实 Chromium、JavaScript 关闭、外部 CDN 请求阻断的条件下：

1. 通过表单创建项目、添加两个入口、逐个预览并启动匿名扫描。
2. 项目累计 **4 个主体、4 条观察、2 条已保存关系**，不同 origin 的同名路径独立。
3. 给第一个站点的 `/asset` 添加 `reviewed` 标签和备注，筛选刷新后仍匹配 1 条；JSON 下载精确包含这 1 条与备注。
4. 在原生表单中合并同 origin 的两个主体，主体数从 4 变成 3；拆出一条观察后恢复为 4。先撤销拆分，再撤销合并，所有观察的原始 ID、原始归属与展示归属恢复。原扫描报告字节不变。
5. 桌面 1280×900 与移动端 390×844 均可操作，无横向溢出。已检查移动端截图；高级筛选默认折叠。

命令：

```bash
PYTHONPATH=. .venv/bin/python -m pytest -o addopts='' -q tests/test_project_journey_e2e.py
```

在隔离工作区运行时，将 `.venv/bin/python` 换为主仓库虚拟环境的绝对路径。该测试启动本地合成服务，不扫描外部站点。截图输出至 `output/playwright/v07/`，验证日志保存在 `.verification/`，均不进入发布包。

## 登录身份与未知结果

`tests/test_identity_journey_e2e.py` 同时执行原有流程和项目关联流程。合成用户在独立浏览器输入测试验证码，Garden 用新浏览器恢复状态并验证成功元素；之后从带项目入口的身份页面预览、确认采集。项目得到 `/me` 和 `/asset` 两个主体、两条已确认身份观察，按 `target + profile ID` 保存账号归属。移动端项目清单可读，没有把 Cookie 值显示到页面。

专项服务回归还验证：同一路由匿名 401 与账号 200 是一个主体、两条独立身份观察；后一次登录失败不移除历史观察，也不推导资产下线。比较的登录健康状态缺失、配置变化、来源时间缺失、模式变化或补采均保留未知。真实浏览器此轮覆盖一个登录账号；多个同角色账号的采集隔离由现有身份采集回归验证，不冒充为多账号项目 Web 旅程。

## 用户需要理解的边界

- 主体是路由族，不等于业务实体、持续在线或业务有效。原始观察与人工展示归属分开保存。
- 比较需要显式选择两次项目运行；未再次观察到不等于已删除。补采不能证明全站缺席。
- 关系仅来自已保存的页面、脚本或重定向证据。没有保存关系不代表不存在依赖；候选不会升级成已请求资产。
- 合并只允许同 origin、方法、原始类型和规则版本；拆分只处理选定历史观察。依赖后续整理的旧规则不能先撤销。
- JSON/CSV 导出全部筛选结果，Markdown 只提供概要。来源任务删除后保留项目快照，但原证据入口可能不可用。
- 归档保留读取，停止入库和整理。来源内容变化拒绝覆盖已入库快照；入口绑定变化需要重新绑定。
