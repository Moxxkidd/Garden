## 约定与蓝图的关系

- 这组文件把蓝图落实为版本级开发决定；具体范围与默认选择以对应版本规格为准，通用实施流程见开发约定。
- 25% 提升、500ms 查询和 5 秒启动等是需要记录的优化目标，不是无限追加工作或虚构达标数据的理由。功能、数据正确性和必要的有界资源行为仍是验收门。
- v1.1.0 不自动启动桌面实验。蓝图中的提前桌面验证属于 v1.7.0 的第一片；如提前执行，单独启动该片并复用结果。
- 当前主工作区已有应用、测试和演示文档改动。实施时重新检查现场，不把这份索引的“待实施”状态当成代码缺失证明，也不覆盖已有实现。
- 当前 Python 核心要求为 ≥3.10。桌面包固定 Python 3.12，不将这个打包选择扩散为所有安装方式的版本升级要求。
- 执行者只更新本版状态、验收记录及必要的前置接口说明。下一版未做完就保持待实施。

## 状态如何更新

状态依次使用：待实施、实施中、本地验收完成、CI 验证完成、已合并。发布状态另记；“本地验收完成”不能写成“已发布”。如有真实阻塞，写具体缺口与可独立完成的部分，不将整个路线图笼统标为受阻。
