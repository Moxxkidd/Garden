## 1. 目标与现状

解决已出现的四类问题：命令入口仍显示旧版本、SOCKS 代理依赖不完整、数据库 revision 正确但必要列缺失、长来源与扫描进度难读。已有 doctor、安装脚本和来源/进度补丁必须先复用。

本版不新增发现策略、SSE、桌面窗口或通用数据库自愈框架。

## 2. 分片实施

### A · G2-01 安装与版本

- 核对正式 launcher、实际 Python 包及服务进程三者；把版本事实统一到安装包元数据，源码环境沿用一个明确来源，不继续由配置伪装版本。
- CLI --version、页面和 doctor 使用相同版本事实。doctor 显示加载位置、命令入口与数据目录，敏感配置不输出。
- 已有 GARDEN_PROJECT_VERSION 覆盖项如仍存在，只提示已忽略；不要遍历用户机器删除其他 Python 环境或安装。
- 正式安装和升级脚本使用同一入口验证；保留用户配置和已有数据。

### B · G2-02 网络与旧库

- 保留显式代理配置；不默默继承 shell 中的代理。安装依赖启用 HTTPX 的 SOCKS 支持，避免配置成功却运行时缺依赖。
- 现有诊断增加代理类型和依赖可用性；目标连接测试单独由用户触发，只执行一次受现有范围/超时约束的 GET，区分连接失败、代理不可用与目标 HTTP 错误。
- 针对已知 scan_contexts.temporary_secret_ref 漂移核对列和唯一约束；使用新 Alembic 迁移修复，并兼容列已被手工补齐的数据库。不要做任意 schema diff 后自动修复。
- doctor 保持只读；常规启动给出明确升级提示。升级命令在修改前备份，并保持现有显式升级模型。

### C · G2-03 来源与进度

- 先检查来源弹窗、pending_count、CLI 活动反馈等本地改动是否已经存在或合入；复用有效补丁，避免重复实现。
- 来源详情使用有界独立面板；表格显示摘要和数量。窄屏没有页面级横向溢出，键盘可打开/关闭。
- 采集中显示实际请求、响应、候选、待处理和耗时；终态与覆盖完整性分开展示；不按时间虚增百分比。
- 对此次已复现的网络失败提供中文处理提示；未知错误保留原始代码，不建立通用建议推理器。
