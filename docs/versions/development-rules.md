# Garden 分版本开发约定

日期：2026-11-03。适用于本目录九个版本；核心要求是**实现可验证的当前需求，减少防御性编程与重复验证**。

## 1. 启动与范围

1. 读取仓库及相关目录中实际存在的 AGENTS.md、本文件、本版规格和前置版实施记录。不存在的交接文件不是新增文档工程的理由，不凭历史对话编造内容。
2. 核对分支、HEAD、远端信息和工作区差异；记录本版基线。主工作区有无关修改时，复用合适隔离工作区，或在 codex/版本-主题 分支中隔离实现。不得清空、覆盖或混入他人的改动。
3. 对照当前代码确认哪些已做、哪些需改。前置能力已经存在就直接复用；前置标签与代码不符时记录实际缺口，不擅自补做整版前置需求。
4. 常规实现选择在规格内自主决定；仅真正改变授权范围、兼容承诺或存在不可独立解决的依赖时提出具体裁定问题。不为新增函数、普通错误处理或已有权限内的操作反复索取批准。
5. 按分片连续完成本版，无阻塞时不停在第一片。不自动开始下一版。

## 2. 少写防御性代码的具体标准

| 情况 | 本项目做法 |
| --- | --- |
| 用户输入与外部响应 | 在已有 Pydantic、网络策略或导入入口验证一次；内部使用明确类型，不重复堆叠 isinstance、getattr 和默认值 |
| 预期业务失败 | 在对应应用入口转换为现有错误形式；只捕获能实际处理的异常，保留原始原因 |
| 程序错误 | 让错误暴露并修复；不使用 except Exception: pass 把错误变成空资产、成功或未知状态 |
| 兼容处理 | 只支持当前文档承诺的接口和实有历史数据；不为假想旧版本建立多层 fallback |
| 重试与超时 | 复用现有预算和网络层；只对已定义的瞬时失败重试，不在各层再包一轮 |
| 抽象与配置 | 优先现有模块或直接函数；第二个真实调用需求出现才提取共用机制，不建立空基类、插件系统和未来配置项 |
| 性能优化 | 先定位真实热点，再修改该热点；不顺带重写全引擎、引入缓存体系或更换数据库 |
| 清理与恢复 | 使用正常 finally/上下文管理和现有事务；只实现本次会触发的失败恢复，不预建所有平台的恢复矩阵 |

这是删减无依据的防御分支，不是删掉必要约束。继续保持目标范围、身份隔离、只读自动采集、请求预算、敏感数据脱敏、数据库约束和真实状态语义。不把失败记成功、不把未观察记不存在、不把人工保留记机器已证明有效。

每次准备新增 fallback、依赖、抽象层或开关时，只需问：本版哪个已知场景需要它？答不出来就先不加。不要求另写审批报告。

## 3. 测试与性能预算

- 对行为变化先用一个有意义的失败场景固定问题；相邻边界用参数化或现有 fixture 覆盖。不要给实现细节逐行配测试，也不强制每个样式调整都写 RED。
- 每版列出的测试文件是复用入口，不是每次编辑都跑一整组的命令清单。开发中选择本次影响的节点；缺失覆盖才新增少量行为测试。
- UI 布局用代表性页面和真实浏览器检查；无需叠加大量“模板包含某字符串”的重复测试。真实浏览器、进程中断和安装实验只用于确实需要它们的行为。
- 代码冻结后，对最终候选执行一次完整 pytest；如果已授权该候选的 CI 全量矩阵，可由该 CI 承担。不同时把本地全量、质量脚本全量、CI 全量当成三个例行必跑项。
- 完整回归发现问题时，先修复并跑相关用例；最终候选必须有全量结果。未授权推送时用本地全量，不为等待未来 CI 把本版留在未验收状态。
- Ruff check、format check 和 git diff --check 在冻结后执行一次；新增代码或发现问题才重跑相关检查。纯文档工作只做文档与差异检查。
- 性能先记录同机同语料基线，小样本定位；冻结后一次正式比较。优化目标未达到时记录实际数字和原因，停止追加无范围的重构；必要的性能功能缺失或明确回退仍需修复。
- 所有测试使用合成账号与本地 fixture；真实目标只在单独授权的范围和预算内验证。日志记录环境、命令、SHA 和结果，不复制敏感数据入库。

## 4. 接口、迁移和版本收口

- CLI、Web、API 共用业务逻辑与结果投影，不各自推断资产数量、身份状态或覆盖结论。
- 只添加本版用到的表、列与路由。新增迁移沿用实际 head，不预占未来编号；不改写已分发迁移。
- 旧数据缺失的新字段如实标记未知或未复核，不回填伪造的历史事实。无模型变更就不新增迁移。
- 单次实施最终确定一种默认实现；不得同时保留多个原型、两套前端或两套调度器作为“备用”。确需兼容的入口应委托同一实现。
- 冻结前更新本版版本号及实际受影响的版本断言、用户文档和必要展示内容。只描述已实现行为，不复制整份未来蓝图到 README。
- 构建/安装验证按变更影响选择：模板/静态资源需检查包内容，迁移需验证旧库升级，桌面需真实打包；不每版重新下载全部依赖。

## 5. 交付与停止条件

在本版“实施记录”填写真实基线、改动、验证结果、未验证环境和遗留项，并更新索引。验收条件全部满足即结束本版；优化愿望转入后续，不为追求抽象完美延长工期。

提交、推送和 PR 按**当前会话对本版的授权**执行，不能借用其他版本的旧授权；已授权时完成交付并核实远端 SHA，禁止 force push。未授权时交付本地改动、验证结果与待提交范围，不反复追问。

不得自动 merge、创建 tag/Release、上传软件包、升级用户日用数据库、重启日用服务或调用发布凭据。需要这些动作时应已有相应授权；构建临时候选包、使用合成数据库和隔离运行环境属于正常本地验收。

最终报告只需：完成范围、关键验证、剩余限制、提交/推送的实际状态。历史绿灯不得用作本次结果。
