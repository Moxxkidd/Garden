# v1.5.0 · 报告与资产交付

状态：本地验收完成，待最终候选完整 CI。对应 G2-16—18。前置：[v1.4.0](v1.4.0.md)。遵守[开发约定](development-rules.md)。

## 1. 目标与范围

让同一资产视图能生成可读报告、完整数据清单和离线交接包；解决大结果先全量装入内存的问题。沿用 delivery-v1、脱敏、项目修订和现有渲染，不做通用模板设计器、插件导出平台或全新 PDF 引擎。

## 2. 分片实施

### A · G2-16 三层报告

- 统一概要、资产、证据三层投影。概要包括范围、身份、执行状态、资产分类、缺口、人工复核和下一步；资产层来自当前筛选；证据层保存可追溯引用。
- CLI、Web、Markdown、HTML 使用同一计数与语义。不要分别解释“有效”或把证据数当资产数。
- 合并重复说明，用一个公共术语区解释未知/未覆盖，行内只显示相关事实。保留旧报告，不原地重写。

### B · G2-17 大清单与可读 CSV

- 复用目录查询，采用分块迭代；数据分页应下推查询，不先组装全部结果再切片。
- 保留旧机器 CSV 和 delivery-v1，新增明确的 readable CSV 选择。常用列固定为资产 ID、URL、方法、类型、状态码、身份、最近观察、复核状态、来源引用。
- 多身份以独立观察行表达，不拼成无法解释的隐式主身份；公式防护、HTML 转义和脱敏复用现有实现。
- 新增本地导出任务，提交时冻结查询、项目 revision 和输出格式。复用有界执行器，分块生成脱敏文件；完成后才提供下载，不让慢下载长期占用数据库读取快照。
- 导出期间状态为生成中/已生成/失败/已取消；下载显示“已发起下载”，不要声称已保存到用户磁盘。重启中断任务标失败/中断，不偷偷自动重做。

### C · G2-18 离线 HTML、PDF 与 ZIP

- HTML 内含所需样式和资源；默认无远程请求。证据只带公开引用与允许的脱敏内容，缺失部分写明未包含。
- PDF 复用 Playwright Chromium 渲染同一 HTML，不新增排版服务；不可用时只提示 PDF 不可用，其他格式保持正常。
- ZIP 包含清单、概要、来源索引、schema/字段说明、范围/身份/预算和版本信息；不含原始 Cookie、Token、私有会话文件或未脱敏正文。
- 每个文件引用同一生成快照；不同格式不在生成过程中各自重新查询“最新资产”。

## 3. 接口与数据

复用[资产交付](../../app/services/asset_delivery.py)、[项目导出](../../app/services/project_export.py)、[交付路由](../../app/api/routes/delivery.py)。新增导出任务提交/状态/下载入口，旧同步接口仍可用并委托同一投影，不制造第二套字段定义。

导出任务只保存配置、修订、状态和受控产物引用。交付仍使用 delivery-v1；新的人类可读 CSV 明确标识格式，不修改旧 CSV 字段。无需更换数据 schema 主版本。

### 真实 20 页 PDF（AC06）

- 最终命令：使用合成库的 `python -m app.cli.main projects deliver 1 --format pdf --filters '{"q":"pdf20"}' --output output/pdf/v150-delivery.pdf`。样本为 90 个主体、90 条观察，真实输出 20 页 A4、631,120 字节；SHA256 `e31965f19f3cbc25f9c43509b9c6b9d647e271f7d39a31953cdc252ce09363b2`。
- 实际目检发现本机 Chromium 打印 PingFang 字体丢中文字形；最小原生字体探针排除 CSP，Heiti/Songti 可嵌入。最终采用可嵌入的系统中文字体设置，无新增字体下载/引擎或多浏览器 fallback。最终中文标题与每页中文文本提取通过。
- Playwright 的 pdf() 原生实现会收集完整二进制；本版复用同一 Chromium Page.printToPDF/ReturnAsStream，以 IO.read 每 64 KiB 写出，并检查取消信号，不先持有整份 PDF bytes。浏览器只允许读取本 HTML，其他请求禁止。
- 已把全部 20 页渲染为 PNG 做逐页联系图检查，并放大第 1、11、20 页核对标题、表头、长 URL、资产/证据章节衔接、中文与页脚；没有裁切、重叠或缺字。文本边界检查为 0 个越页词，页码 1—20 连续。
- 样本只留本地 `output/pdf/v150-delivery.pdf` 与验证目录，不提交二进制。没有以模板字符串断言代替真实 PDF。

### 边界与剩余限制

- 本版仅 G2-16—18，不进入 v1.6.0。无 PR、tag、Release、软件包上传、日用数据库升级或日用服务重启。
- 分块/内存规模证据针对完整 JSON 文件任务；PDF 的浏览器布局仍随页数占用内存，OpenAPI 草稿需要聚合路径。旧 Python 字符串/完整列表便捷接口按返回类型保留物化语义；HTTP/CLI 大清单走文件路径，不将这些兼容函数冒充流式。
- 每块 200 条，单条历史记录内的既有集合不裁剪；来源范围元数据仍随来源数增长。不声称任意输入总内存常数或优化了真实目标扫描速度。
- PDF 需 Chromium 和系统中文字体；实测为 macOS，未做 Windows 或其他中文字体环境的实际 PDF 验证。公开引用可指向已移除的源任务，此时保存快照仍在，界面如实提示来源不可用；不复制私有证据正文。
- 产物保存在本机受控目录，本版不新增自动过期清理。生成/下载/用户保存分别表达；浏览器保存成功不由服务端推断。
