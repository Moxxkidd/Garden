# v1.6.0 · 持续更新与数据管理

状态：本地验收完成，最终候选待 CI；未发布。对应 G2-19—21。前置：[v1.5.0](v1.5.0.md)。遵守[开发约定](development-rules.md)。

## 1. 目标与范围

让项目按明确范围周期复查，展示资产时效和变化，并能备份、归档和清理本地数据。复用已有比较与增量采集，不做分布式调度、远程通知、云同步或通用备份框架。

## 2. 分片实施

### A · G2-19 时效与变化

- 项目显示最后观察时间、对应身份、范围和预算，以及新增、属性变化、未再次观察、待复核分类；复用现有 comparison，不另算一套差异。
- 默认将超过 7 天未观察的项目资产标为“较旧”，只作时间提示，不能据此变成不存在或无效；每个项目可设置一个新鲜度天数。
- 复核状态保留；仅当实际观察属性有变化时标记需复核，单纯再次观察或时间变旧不重置人工决定。
- 增量计划优先选择已有缺口和较旧资产，仍通过既有预览/确认，显示使用的旧证据与本次预算。

### B · G2-20 周期复查

- 首版只支持固定间隔小时，范围 1—168，默认 24；保存显式开始时间与 UTC 下次时间，界面显示本地时间。不引入 cron 语法、自然语言时间或第三方调度服务。
- 周期任务绑定项目入口、身份、最终参数和预算快照，默认关闭；开启前显示会自动发送请求的范围。入口/身份配置变更后暂停该计划并要求重新确认。
- 仅在现有本地服务存活时执行；同项目已有活动任务则记录本次跳过，不积累待发送队列。
- 启动时将已经错过的计划记为错过并推进到下一未来时间，不立即补发。身份失效则暂停计划，不自动降级匿名。
- 执行复用现有 start_scan/项目计划和同源 admission。使用现有单进程部署模型，不加系统启动项、远程 worker 或邮件。

### C · G2-21 本地数据管理

- 项目归档只改变可见状态并暂停相关计划，不删除历史观察。存储页显示数据库、证据和生成导出文件的占用。
- 备份仅在没有活动采集/导出写入时执行，复用执行器所有权阻止新任务；SQLite backup 与引用的私有材料形成同一备份集，包含版本与清单。
- 备份是私有数据，不是可分享交接包：目录 0700、文件 0600，并明确提示可能包含会话材料。首版不自造加密协议。
- 恢复到用户选择的空目录，完成一致性检查后再明确切换；不覆盖正在使用的数据目录。
- 清理只处理过期导出产物、已确认无引用的临时材料和用户明确选定的归档清理项。先预览数量/空间，再确认执行；引用中的证据保持可用。

## 3. 接口与数据

复用[项目比较](../../app/services/project_comparison.py)、[增量计划](../../app/services/project_incremental.py)、[项目生命周期](../../app/services/project_lifecycle.py)。增加项目周期计划的查询/启停/运行历史、归档和本地备份操作；不把后台自动触发散落到页面查询中。

计划最小保存项目、配置快照、间隔、开始/下次时间、启用状态与上次结果。已有任务是实际执行事实，不复制成另一套任务历史。备份清单只负责版本/文件核对，不成为通用文件数据库。
