# v1.4.0 · 身份采集与多入口

状态：本地验收完成，待最终候选完整 CI。对应 G2-13—15。前置：[v1.3.0](v1.3.0.md)。遵守[开发约定](development-rules.md)。

## 1. 目标与范围

把现有登录、验证、采集和补采组织为连续流程；支持用户主动浏览时收集资产，项目内多个明确入口分别绑定身份。此版不建设通用 SSO 自动化、验证码识别或录制后自动重放业务流程。

## 2. 分片实施

### A · G2-13 登录与健康引导

- 复用人工登录和独立身份服务，界面连续呈现待登录、待验证、可用、失效、无法确认；显示绑定入口和最近恢复验证时间。
- 保存前沿用已有“关闭原会话，用新上下文恢复并正向验证”规则；不得以 Cookie 文件存在代替可用性。
- 验证失败显示具体步骤及处理入口，保留旧有效会话直至新会话确认；不新增全自动登录失败重试链。
- 采集中身份失效停止该身份的新工作，其他独立身份继续。重新登录后通过现有补采预览恢复，不悄悄变成匿名。

### B · G2-14 人工浏览采集

- 显式进入“人工浏览采集”，打开独立受控 Chromium；用户手动登录、验证码和浏览，页面持续显示采集已开启及停止入口。
- 目标请求由用户操作和浏览器产生；记录实际观察，不自动点击、提交、刷新或重放用户动作。请求预算耗尽后停止 Garden 的采集会话，并给出原因。
- 用户主动产生的非 GET 请求可以成为已有请求/观察模型中的记录，标明 manual 来源；它们不得进入自动队列和自动补采。
- 只采集计划中批准 origin 的资产；登录域只用于完成用户登录，不自动列为扫描范围。敏感字段沿现有受保护存储和脱敏投影处理。
- 人工会话结束后按既有流程完成身份确认与观察入库，避免在响应未保存时提前关闭；复用此前浏览器收尾修复。

### C · G2-15 多入口计划

- 使用现有项目入口，每个入口选择明确身份；计划展示全部入口与总预算后提交。
- 首版采用“一入口/身份一个子任务或队列”的组合，聚合到现有项目运行；队列保留单 origin 约束，不重写网络层为任意跨域抓取器。
- 总预算按入口顺序确定分配，用户可在预览中调整；子任务总配额之和不超过计划预算，第一版不动态借用其他入口剩余额度。
- 跨 origin 链接作为候选提示；用户添加为项目入口后，才在新计划中采集。已有任务的范围不原地扩大。
- SSO 允许域与采集 origin 分开配置；默认都是入口 origin。额外登录域只在用户开启人工登录时生效，不授权自动采集身份提供方。

### 实现决定与范围

- G2-13：身份页只读投影待登录、待验证、可用、失效、无法确认；保留入口导航和最近恢复验证时间。登录失败显示打开窗口、状态快照、恢复验证等具体步骤。旧有效会话在新恢复验证成功前保持不变。
- 入口是操作引导上下文，不把独立身份永久绑定到项目生命周期：LoginAttempt 保存返回入口；私有 verification 配置不保存该导航字段。应用回归证明归档项目不应使同一 Target 的已验证身份失效。身份仍以原 Target/profile 隔离。
- G2-14：默认 automatic；manual 必须显式选择一个身份，禁止与匿名/自动持久队列混用。可选本次人工登录阶段复用 ManualBrowser 和原恢复服务，先关闭原窗口，再用新上下文正向验证；之后打开独立 Chromium 供用户浏览。额外登录 origin 仅在这段显式登录窗口生效，采集始终只允许本子任务入口 origin。
- 首次健康验证移到人工浏览导航之前，避免 Chromium 恢复证明占用被暂停导航的超时；仍用原 IdentityHealthGate，验证请求继续计入同一预算，不新增验证次数或重试。采集中身份不能继续确认时停止该身份新工作，不变成匿名。
- 人工记录复用 BrowserDiscovery 的 CDP/响应收尾；只做用户显式开始触发的一次入口导航，不自动遍历链接、点击、提交、刷新或重放。控制页持续显示记录状态与停止入口。用户/浏览器实际产生的 POST 可保存为原 ScanRequest/观察，`capture_source=manual`、禁止重放；记录方法、脱敏 URL、响应及来源，不复制 POST 请求体。POST 不放入自动队列或恢复检查点；已知不确定 GET/HEAD 仍可显式补采。
- 结束时先冻结新发送、等待已经发出的响应保存、完成批次身份确认，再关闭原浏览器；只有新上下文恢复证明通过才保存新状态。预算耗尽/停止/失效保留已有观察，覆盖仍不完整。验证请求的每一跳重定向统一复用既有 CDP 准入计费，修复普通恢复验证漏计重定向的实际失败；保存动作本身不当作网络请求计费。
- G2-15：项目现有入口选择明确身份或匿名；按入口顺序对剩余预算确定分配，单子任务 1—2000 次，显式配额之和不得超过计划总额，未分配额度不动态借用。可调整后重新预览，提交绑定现有目标、身份、会话与项目修订；变化后须重新预览。
- 计划使用现有单入口身份子任务默认模式，不默认开启可选持久队列；每个子任务继续执行单 origin 网络护栏和同一请求/健康预算。原持久队列实现未改为跨 origin 队列。子任务结果汇入现有 ProjectRun；跨 origin 链接只保留候选，须用户另加入口并新建计划。
- 新迁移 `0014` 接实际 `0013`，只新增请求来源列和 reference-only identity_plans。旧请求新来源列为 NULL/未知，不伪造历史；计划只保存 entry/profile ID、模式、配额、子任务 ID 及启动错误，不复制 Cookie、令牌或认证文件。重复提交相同预览返回同一计划，未增加认证中心或第二套执行队列。
- 扫描详情通过共享 ScanRunView 的可选 `interaction_mode` 字段呈现人工控制入口；旧任务为未知，不在页面适配器另查数据库或推断模式。相邻页面回归发现重复查询后改回统一投影。
