# v1.2.0 · 有效发现与预算调度

状态：本地验收完成，最终候选完整 CI 待运行；未发布。对应 G2-07—09。前置：[v1.1.0](v1.1.0.md)。遵守[开发约定](development-rules.md)。

## 1. 目标与范围

在固定请求预算内增加不同功能路径的观察，复用现有 priority、路径变体限制和 HTTP/浏览器采集。混合模式首版面向匿名单入口；登录身份继续现有浏览器流程，在 v1.4.0 整合多入口。不提前实现完整 SPA 点击遍历、自动业务流程或机器学习排序。

## 2. 分片实施

### A · G2-07 可解释调度

- 把数字/日期路径族识别提取为小型共享函数，供普通与持久 HTTP 调度使用；保留原始 URL 和精确资产身份。
- 调度采用确定性顺序：新路径族的首个候选优先于已观察路径族的新实例；同档按来源轮转，来源内按发现顺序。入口与已要求的验证请求沿用既有优先级。
- 来源分为页面、Sitemap、JS、导入四组，空组跳过；不引入可调权重、评分模型和大量配置。
- 普通扫描复用策略函数，不强制创建持久队列；持久扫描使用现有队列状态。记录选择和暂缓理由。

### B · G2-08 相似内容采样

- 继承已有 max_variants 语义，数字/日期路径和同参数名组合先采样，再处理剩余候选。查询参数值不直接假定等价。
- 重复来源保留有界摘要；未请求候选保留具体原因与数量。增加预算的补采复用现有预览/确认。
- JS 只补实际 fixture 中明确的字符串路由、fetch/axios 线索；复杂表达式保持候选未知，不执行站点 JS 来猜 URL。

### C · G2-09 预设和混合模式

- ScanOptions 增加可选发现策略和 collection_mode=hybrid；旧请求缺少新选项时使用原含义。预设在提交前展开成实际参数，服务端保存最终参数快照。
- 界面提供快速、平衡、浏览器深入三个预设：快速沿用 HTTP 默认；平衡启用多样性调度与 HTML/JS/Sitemap；浏览器深入使用明确混合模式。高级参数仍可调整。
- hybrid 使用统一持久预算：先为浏览器预留总请求预算的 30%（向下取整且不超过 max_browser_requests），HTTP 使用其余预算；没有触发浏览器时将预留还给 HTTP。两者共用总截止时间。比例先作为实现常量，预留为零时明确本轮没有浏览器额度。
- 仅因已有 Hash 路由线索，或入口无普通同源可访链接但有脚本资源时，选择有界浏览器导航；静态页面不自动付出浏览器成本。不自动点击业务按钮。
- 浏览器不可用/启动失败时保留 HTTP 结果并明确未覆盖部分；不再套另一种浏览器或静默宣布完成。

### G2-07—08：调度与采样

- `discovery_scheduling.py` 的小函数统一数字/日期路径族、参数名组合和选择顺序。origin / method 保留在族标识；持久队列仍按 origin、身份绑定，已分发的 route_key 编码保持兼容。精确 URL / method 的请求键、资产和身份观察不作归并。
- 入口和既有 priority 0/1 保持优先；其他候选先选新路径族，再依页面 → Sitemap → JS → 导入轮转，来源内按发现顺序，跳过空组。持久调度复用原队列状态和 telemetry 的来源游标；普通扫描复用策略及原列表，无需启用持久模式。已在途候选占用族机会，避免并发时重复抢同一族。
- 普通模式仅显式 `discovery_strategy=diversity` 时采样，`max_variants=20`；持久模式沿用 `durable.max_variants=20`。日期、数字与相同参数名组合先受此上限约束；不同参数值保留精确请求身份。上限之外保留候选和 `max_variants` 原因，并扩展原结构化覆盖缺口显示具体数量，不写“未知”。原无新参数的页面优先顺序保持不变。
- 候选保存选择/暂缓理由，重复来源继续复用原有最多 20 条摘要及截断标记。持久队列可列出/导出未覆盖项，增加预算的补采继续用原预览和确认；普通扫描可沿用配置重新预览。没有自动扩大授权范围。

### G2-09：预设与混合预算

| 预设 | 实际模式 | 多样性 | Sitemap / JS | 其他预算 |
| --- | --- | --- | --- | --- |
| quick · 快速 | http | 原含义 | 关闭 | 原 HTTP 默认 |
| balanced · 平衡 | http | diversity | 开启 / 开启 | 原页面/资源/超时默认，可覆盖 |
| deep · 浏览器深入 | hybrid | diversity | 开启 / 开启 | 无显式 durable 时使用原 CollectionOptions 默认 |

- `preset` 可选；显式字段覆盖预设。Web 先预览实际展开值再确认；CLI `--preset` / API `options.preset` 共用服务端展开。CLI 本机 API 使用 exclude_unset 保留“未指定”语义，避免默认 false/http 悄悄覆盖预设；真实本机 HTTP 传输用例验证 deep + 50 总请求 + --no-js。
- 服务端保存展开后的最终参数快照。hybrid 自动使用持久队列，仍仅允许匿名 quick 单入口；认证和独立身份不接入新的混合调度。入口 Hash 材料通过原受保护输入存储保存，只公开摘要/哈希，不把路由参数值写入公开 options。
- 浏览器份额是实现常量 **30%**：`min(floor(total * 30 / 100), max_browser_requests)`。HTTP 阶段在原 admission 处限制其余份额，所有重定向/重试逐请求收费；没有满足触发条件则同一租约继续 HTTP 并归还预留。没有第二轮重试或重新创建队列。
- 仅 Hash 线索或“入口有脚本资源而没有普通同源可访链接”触发 Chromium。浏览器仅从允许的导航进入，按原队列过滤后续工作；总截止时间不重置。零份额不启动浏览器，Chromium 不可用保留 HTTP 结果并显示未覆盖；不自动点击业务按钮、不换另一浏览器。
- CLI、Web、Markdown 报告共用 `discovery_explanation`，显示路径族/未请求原因数量、触发条件、预留额度、HTTP / 浏览器实际请求及新增观察；观察不冒充有效资产。旧任务缺少摘要字段仍保持未记录。

### 固定 50 次请求的真实合成实验（AC06）

同机 loopback HTTP/1.1 语料：60 个日期详情、60 个数字详情、40 个功能页、5 个 Sitemap 功能页、JS 字面路由/fetch 与 Hash 路由。三轮语料 SHA256 相同，均无真实目标；请求预算、页面/资源上限和采样上限相同。基线运行实际前置源码 f12af2c；新候选记录 Git 基线与 Python 源码摘要，完整结构化证据见 [v120-discovery.json](../benchmarks/v120-discovery.json)。

| 候选 | 实际请求 | 请求覆盖路径族 | 同族重复请求 | 功能路径 | 扫描耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| v1.1.0 原顺序 HTTP | 50 | 12 | 38 | 8 | 1.7933s |
| v1.2.0 多样性 HTTP | 50 | 50 | 0 | 45 | 2.0495s |
| v1.2.0 多样性 hybrid | 50（HTTP 35 + 浏览器 15） | 49 | 1 | 43 | 5.2977s |

- HTTP 路径族数量 **+316.67%**，超过 25% 目标；原先观察到的 8 条功能路径全部保留。混合轮额外记录 14 条浏览器新增观察；其 49 个请求路径族与路由视图/资产数不是同一指标。
- HTTP 耗时约 +14.3%，没有声称吞吐更快；混合轮包含 Chromium 启动和渲染成本。单次固定语料样本，不是互联网召回率或统计压测，不为追数追加规则。
- 真实命令：`PYTHONPATH=. <test-python> scripts/benchmark_discovery_budget.py --source-root ../v110-performance --output .verification/budget-baseline.json`；候选使用 `--strategy diversity`，混合另加 `--mode hybrid`，最终输出为 budget-diversity-final / budget-hybrid-final.json。脚本创建独立临时 DB 和 GARDEN_HOME，不接触日用数据。
